# awesome-vtt – project notes

In-person table mode for Foundry VTT **v14** and **dnd5e 6.0.x** (built against 6.0.5, verified with 6.0.6), by Stefano Pignataro.
Sister module: `../awesome-vtt-mobile` (phone companion).

## What it is
- One screen under a glass table, logged in as a dedicated Player-role user ("Table"). It shows 12 seats (3 per edge), each rotated to face its player.
- Input is a **shared mouse/trackpad, not touch**.
- Seats map to actors, not users. Saving seats grants the table user Owner permission; clearing a seat restores the previous level (`ownership.mjs`).
- Private information needs the player's own login on a phone (see awesome-vtt-mobile). The table screen is visible to everyone.

## Decisions agreed with the user
- **Keep the modules in sync (standing rule from the user):** every time something is added, removed or changed in the table or phone module, do the same in the other one through `awesome-vtt-core` (shared logic there; only templates, CSS, UI text and device-specific layout per module). If it's unclear whether or how a change applies to both, ask the user first.
- **Pill layout (user's decision, 2026-09-30, like the phone):** three rows from the player's edge inward: the section bar (core `SECTIONS`: character, dice, chat, journal, compendium; icon above a small label, `togglePanel`), map tools + Settings gear (always icon-only), and the player pill (portrait, HP, stats, Quick actions bolt, ADV/DIS chip). **One panel open at a time per seat** (`state.panel`: "quick" or a section). **Folded pill (user's decision, 2026-09-30):** with the "Fold pill rows" client setting (default on) only the player pill shows; the tools row and section bar open below it (from the pill's bottom, pushing the player pill up) when the pointer is over a 0.8em band above the pill, the pill, or any of the seat's controls (`.avtt-seat:hover`), while a panel is open (`.avtt-panel-open`), or on keyboard focus; they fold 350 ms after the pointer leaves. CSS only (grid-template-rows 0fr/1fr on `.avtt-pill-more`); `Seat#pillDepth` always returns the unfolded depth so corner reservations don't change. The "Icon-only pill buttons" setting (per browser, default off) hides the section labels. Buttons without a visible label use Foundry's native tooltip (`data-tooltip=""` + `aria-label`). Each seat sets `data-tooltip-direction` (toward the table centre) and `data-tooltip-class` (`avtt-tooltip-<side>`), so core's `#tooltip` opens and rotates toward that player; dnd5e chat-card tooltips inside a seat benefit too.
- **Advantage (user's decision: the phone model):** one `advMode` per seat, set in the Dice panel's Next roll and in prompts, shown as a chip on the player pill, used by every d20 roll from the seat (sheet, dice pool, prompts) and reset after one roll. No separate dice-panel mode or sheet toggle.
- **Physical dice:** a registered dice fulfillment method (`scripts/dice/`). The world setting chooses whether the player, the GM, or either one enters results. The GM can also let Foundry roll.
- **Dice So Nice:** optional integration via its own setting.
- **Core UI hiding:** hidden with CSS only, including the scene controls. The module still drives core UI from code, e.g. the ruler via `ui.controls.activate`.
- **Map tools on the pill:** Select, Hand (next to Select, user 2026-10-04), Target, Ruler, Zoom in, Reset zoom (`canvas.animatePan({ scale: 1 })`; core has no reset-zoom control, `canvas.recenter()` only re-centres on the controlled token), Zoom out and My token, then Settings, in their own row, always icon-only. Each row stays on one line. `TableOverlay#fitPills` measures each pill's widest row (sections with labels) and uses `table/fit.mjs` (`allocateEdge`, a pure function) to share each edge: pills grow into free space, and are narrowed (labels hidden via `.compact`) only when an edge can't fit them. Narrowed pills on an edge all get the same width (the largest common cap that fits); pills needing less keep their own width. Corners are reserved for the adjacent edge's corner pill. Foundry v14 has no hand/pan tool; this was confirmed in the source and the official docs (Game Controls: right-drag or Ctrl + arrows). Hand mode is the module's own (`table/canvas-tools.mjs`): a window-level capture listener takes left-drags on `#board` and calls `canvas.pan`.
- **Settings window:** the pill's gear opens Foundry's settings centered, rotated toward the seat, and not draggable.
- **Action info:** each action row has an info button (`invDetails`, like the inventory) that shows the item's description under the row. The phone has the same button.
- **Full sheet and level up (table only):** Full sheet is a round button on the player pill, next to Quick actions (the user asked for it there; the sheet header no longer has the full-sheet button). Level up moved to the character panel's header, at the right of the name and level, above the tabs (user, 2026-10-04; dnd5e only, since SotDL's `levelInfo` has `canLevel: false`). Level up opens Hero Mancer's window (`game.modules.get("hero-mancer").api.openLevelUp(actor)`, its documented public API) when it is active, otherwise the character's sheet (core `openLevelUp`); the user asked for no levelling logic of our own. By the user's decision the phone has neither, so these are a deliberate exception to keeping the modules in sync.
- **Actions from a seat (`table/use-checks.mjs`, three client settings, all on by default because the user asked for them):** Targets are shared by all seats (one Table user): targets used by a targeted action are cleared (`canvas.tokens.setTargets([], {mode:"replace"})`) when the next targeted action starts, unless new targets were picked in between (user's decision, 2026-09-30). `dnd5e.preUseActivity` returns false with a seat notice when targets (`game.user.targets`), a slot (any slot ≥ the spell's level) or fixed-cost item/activity uses are missing; `dnd5e.postUseActivity` rolls a save's damage and a utility's formula like the card buttons do; `dnd5e.rollDamageV2` used to show damage/healing only; since 2026-09-30 (user asked for results of any roll) the core's `onRollResult` (createChatMessage by this user, after Dice So Nice, blind rolls skipped) shows every roll's result in the roller's seat, text from the core's `rollNotice`, plus the actor's name (small line, `fillNotice` `name`); roll notices use the seat colour as background (user, 2026-09-30) with `--seat-ink` (core `inkFor`, WCAG contrast: #111 or #fff), also used by active/primary buttons; the table passes `shared: true`, so pass/fail follows dnd5e's challenge visibility for other players (hidden at "none"). Known gap: dnd5e's own chat cards in the seat Chat panel are rendered for the Table user as author, so they show DCs even at "none"; left as is (would need patching dnd5e rendering). Notices use `Seat#showNotice`. **Roll damage button (user, 2026-10-10, both modules, all systems):** `notice.action` ({label, run}) adds the sibling `.avtt-notice-action` button (`noticeAction`, core `fillNoticeAction`; a notice is itself a button), shown when the core's `offersDamage(result, autoRoll)` is true, running `sys.rollDamageFrom(message)`; such notices stay 30 s (`NOTICE_ACTION_MS`). Also fixed: `use-checks.mjs` called an unimported `rollNotice` (no roll notices showed at all), now `sys.rollNotice`. The pill's Target button is core's "target" token tool.
- **Aligned with the phone (user's decisions, 2026-09-30):** Quick actions panel = the phone's launcher (HP field with Damage / Heal / Temp lives there, not in the sheet; Status tab = conditions only); automation prompts = the phone's (core `prompts.mjs`, same setting keys, shown in the character's seat); chat has All / Mine on both and a message box on the table. Initiative (user's decision): the core's `rollInitiative(actor, mode)` everywhere (strip buttons and prompts): no dnd5e dialog, the Next roll choice on top of the actor's own modifiers (only an armed choice is passed, so dnd5e's automatic advantage stays), for the shown character's combatants without initiative (`initiativeDue`).
- **Busy buttons:** actions in `BUSY_ACTIONS` (seat.mjs) disable their button until `#dispatch` resolves; add new submitting actions there. Effect changes are also queued in the core library.
- **2026-10-04 batch (user's requests; only syntax-checked):**
  - **Hand pan fix:** core's `canvas.pan()` calls `MouseInteractionManager.emulateMoveEvent()`, which dispatches a synthetic `pointermove` on `#board` with the last position PIXI saw (before the drag, since the drag's events are kept from PIXI). The hand handler took it as a move: jank, and the map jumped back to its start. Now only `isTrusted` events count, the pan is absolute from the drag's start (pivot − travel / scale), once per animation frame.
  - **Seated tokens always visible (`table/visibility.mjs`):** wraps `Token#isVisible` (true for seated actors' tokens unless GM-hidden or on another level) and `Token#_isVisionSource` (their vision always counts, even when another token is controlled). Installed at "setup" on the table client; `refreshSeatedTokens()` on seat changes.
  - **Tooltips (`table/tooltips.mjs`):** wraps `game.tooltip._setAnchor`: for elements in a seat or in a window turned toward one (`.avtt-rotated[data-avtt-seat]`), adds `avtt-tooltip avtt-tooltip-<side>` and places the tooltip by its turned footprint toward the table centre. Needed because dnd5e elements set their own `data-tooltip-direction`/`-class` (closest wins), dnd5e re-places rich tooltips through `_setAnchor`, and rotated windows (full sheet) had no attributes at all.
  - **Quick actions:** also list the character's actions (partial `templates/actions.hbs`, shared with the sheet's Actions tab). Quick actions are now `state.quick` (boolean) beside `state.panel` (one section): both stay open side by side when `fitsSideBySide()` (panel widths from `PANEL_EM` ≤ `TableOverlay#freeSpan`, the room along the edge up to neighbours' open panels / corners); otherwise opening one closes the other, and a neighbour opening a panel closes a seat's quick actions if they no longer fit.
  - **"Close other seats' panels"** (client setting `closeOtherPanels`, default off, user's request): opening a panel closes the other seats' panels (`TableOverlay#onPanelOpened`).
  - **Number pad (`table/keypad.mjs`, table only; the phone uses the system keyboard):** a standalone panel (`.avtt-panel.avtt-keypad`, appended to `.avtt-drawers`, user's choice 2026-10-04) titled with the field's label, open while a number field has focus; digits / C / ⌫ / − + (hold repeats, faster after 10) / OK; keeps focus in the field (pointerdown preventDefault); `input` per press, `change` on close.
  - **Attack damage:** the core's `rollDamageAfterAttacks`, under the existing `autoRoll` setting, for seated characters (dnd5e only since 2026-10-10: the SotDL adapter does nothing).
  - **Spells tab** (core `getSpells`, `spellPrepare`), **Party section** (optional shared inventory module, `../awesome-vtt-shared-inventory`), `invToParty` inventory button, compendium entries draggable.
- **Pill stats tooltips (user, 2026-10-04):** AC, initiative, speed, inspiration and condition icons under the HP bar have `data-tooltip=""` + `aria-label` (`AVTT.Pill.Stat.*`). Quick actions panel is 25em (`PANEL_EM.quick`); the character panel is at least 24em and widened after each render to fit all its tabs on one line (`Seat#fitSheetWidth`: the tab row at max-content, measured with getBoundingClientRect (its height for the ±90° seats) because offsetWidth rounds down and half a pixel short wrapped the last tab, found with a headless Chrome probe using Foundry's fonts; +1px margin; `drawersWidth` uses the measured width). A line separates the tabs from the content (`.avtt-panel > .avtt-tabs`). Tab labels never wrap (`.avtt-tabs button` nowrap, sized by content; the row wraps instead).
- **Quick actions remembered + pinned actions (user, 2026-10-04, instead of embedding quick actions in the pill, which would break pill fitting/folding/corner reservations):** client setting `seatPanels` (config false) stores `{ quick, quickTab, sheetTab }` per seat key (`Seat#saveState`, debounced); the first `#renderNow` calls `renderPanel()` so a remembered open panel shows. Favorites (user, 2026-10-04, replacing the always-visible pinned strip): the first row of `.avtt-pill-more-rows` (folds with tools/sections) shows up to 8 dnd5e favorite items (core `getFavoriteActions`, `useItem` buttons) or a hint; rows in Actions, Spells and Inventory have a star (`toggleFavorite`, core `toggleFavorite` → dnd5e `addFavorite` / `removeFavorite` with `buildRelativeUuid`, as dnd5e's sheet; shown when core `canFavorite`). `measurePillNeed` counts the favorites row like the tools row.
- **Open panels are fully opaque (user's decision, 2026-10-04):** the idle fade (`idleOpacity`) applies only to pills and the initiative strip; `.avtt-panel` has full opacity and a solid background (`--avtt-bg-solid`).
- **Shadow of the Demon Lord (phase 1, 2026-10-04):** the seat uses the core's `system.mjs` adapter (no direct dnd5e imports); SotDL-specific bits: `useItem` goes through `#d20` when `sys.FEATURES.itemRollMode`; the initiative strip shows Fast / Slow (`turnSpeed`) when `sys.turnSpeed(actor)`; templates read `stats`, `inspirationLabel`, `deathSave`, `rests`, `tracks`, `checkLabel`, and roll-mode `text` / `tone`.
- **Seat choice for every user (user's request, 2026-10-04; taken seat = swap):** `seat-moves.mjs` (`seatOf`, `movableActors` = characters the user owns, `seatOptions`, `moveSeat`); the `seatPicker` settings menu (not restricted, `apps/seat-picker.mjs`) lists them (on the table: the seated characters, opened from the seat gear's settings window). Seats are a world setting, so players' moves go over `module.awesome-vtt` (`type: "moveSeat"`) to the active GM, which checks Owner permission (sender id from the server) and saves; unseated characters may only take free seats (then `syncOwnership`). `api` (set at init on every client) exposes these for the phone's Settings tab; the seats setting's onChange also calls `awesome-vtt.seatsChanged`. The GM-only Configure Seats editor stays for table user, names and colours. A login-screen Desktop/Phone chooser was investigated and dropped by the user (a module can't change /join: no module scripts there, Data .html served as text/plain).
- **SotDL phase 2 (2026-10-04):** nothing table-specific: attacks use the map's targets (`sys.useItem`), damage after attacks / prompts / favorites / Party come from core and the shared inventory module (see their notes).
- **Out of scope for now:** Actor Studio and Pixels support.

## Working on it
- **Status:** not yet run in a live world; changes are only syntax-checked. Ask the user for console errors or screenshots after testing.
- **Foundry v14 source:** the core zips are in `/Volumes/appdata/foundry-vtt/data/container_cache/`. Unzip `client/*`, `common/*` and `templates/*` into the scratchpad and read the real API instead of guessing. The zip's `node_modules/handlebars` can precompile templates to check syntax.
- **dnd5e source:** `../../systems/dnd5e/dnd5e.mjs`.
- **Shared code:** lives in `../awesome-vtt-core` (a required library module): `dnd5e.mjs`, `sheet.mjs`, `prompts.mjs`, `dice.mjs`, `panels.mjs`, `ui.mjs`, `journal.mjs`, `compendium.mjs`, `wake-lock.mjs`, imported by relative path (`../../awesome-vtt-core/scripts/…`). Its labels use the `AVTTC.` prefix in the core's own language file. Templates and styles stay in each module.
- **Windows:** each ApplicationV2 template part must render **one root element** (the first bug found).
- **Layout checks in a real browser:** Google Chrome is installed; `--headless=new --dump-dom` on a probe page with Foundry's `public/css/foundry2.css` (from the core zip), Font Awesome and this module's CSS measures layout for real (this is how the pill-width growth was found: Chrome's natural width of column-flex buttons follows their current width, so `Seat#measurePillNeed` measures label text instead).
- **Core button height:** Foundry v14 gives every `button` `height` / `min-height: var(--button-size)` (2em, in a CSS layer). Buttons that are taller (icon above a label) or round need an explicit `height` / `min-height` here, and `.avtt-seat button { width: auto }` beats single-class width rules, so size seat buttons with `.avtt-seat .class`.
- **Checks after edits:** `node --check` on changed `.mjs` files, precompile changed `.hbs` files, and validate `lang/en.json`. Keep the README in step with features.

## Upstream watch

`.github/workflows/compat-review.yml` runs daily and has Claude review this module once for each new version of a dependency, following `.github/prompts/foundry-compat.md`.
- **Game systems:** a release of a system in `relationships.systems` newer than its `verified` version.
- **Foundry core:** a new Stable build, with a light review within the verified generation and a full review for a new generation.
- **Results:**
  - The module is fine: a pull request that bumps `verified`. It goes out with the next manual release.
  - A fix: a pull request.
  - Anything that needs the owner: an issue labelled `upstream-watch` and assigned to the owner.
  - New features worth using: an `enhancement` issue.
- **Access:** Claude works with read-only access (secret `CLAUDE_CODE_OAUTH_TOKEN`). A separate job opens the pull request and issues.
- **Isolation (tested 2026-10-11):**
  - **Before Claude runs:** the review job turns on the action's subprocess secret scrub and installs bubblewrap, so Claude's commands don't see the Claude token or any other process. It also blocks reading other processes' memory and removes sudo, and Docker is switched off (Docker access amounts to root).
  - **After Claude:** the steps that follow ignore variables and PATH entries its commands could plant, and make the diff in a fresh clone.
  - **Publishing:** the report job won't publish output that contains the token, or a piece of it, and deletes the review's artifact.
  - **What's left:** Claude's commands never see the token, so leaking it would take a way around the sandbox. The scan is a second line of defence.
- **Bookkeeping:** `.github/scripts/watch.sh` records what was reviewed on the `watch-state` branch. Run the workflow by hand with `force` to review again.
